## Findings

### 1. BLOCKING — `safePublicationBranch` fails open when `project.default_branch` is unset and the repo's trunk isn't literally "main"
`pkg/standing/standing.go`, `safePublicationBranch` (new, ~line 358) and its
caller `standingEnvelope` (~line 395).

`safePublicationBranch(branch, defaultBranch)` refuses publication only when
`branch == "main"` or `defaultBranch != "" && branch == defaultBranch`. Both
`standingEnvelope` and `AuthorityEnvelopeForLaneWithPolicy` pass
`cfg.Project.DefaultBranch` straight through with no fallback, and
`config.Config.Validate()` (pkg/config/config.go:416) does **not** require
`project.default_branch` to be set. So for any repo configured without
`default_branch` whose actual trunk branch is not spelled `"main"` (e.g.
`master`, `trunk`, `develop`), a standing write lane with git-write capability
and `branch_publication: lane-push` is granted `AllowedBranch` == that trunk
branch — i.e. publish authority to what is actually the project's protected
default branch. This is exactly the invariant the packet requires ("protected
main/default branch") and the one this commit exists to enforce.

Demonstrated directly against the shipped function (temporary test added,
run, then removed to restore the pinned tree — `git status --porcelain`
confirmed clean afterward):

```go
policy := &config.MergePolicy{BranchPublication: config.BranchPublicationLanePush}
lane := config.LaneDef{Role: "harvest", Authority: config.AuthorityWrite,
    Capabilities: []config.Capability{config.CapabilityGitWrite}}
got := AuthorityEnvelopeForLaneWithPolicy(lane, policy, "" /* default_branch unset */, "master")
// got.AllowedBranch == "master"  -- FAIL
```
Output: `GAP CONFIRMED: lane-push authority granted to trunk branch "master"
when default_branch is unset`.

This codebase already has the right fix pattern elsewhere: `pkg/worktree/reap.go:204-205`
defaults an empty `policy.DefaultBranch` to `worktree.DefaultBranch` ("main")
before use. The new authorization path in `pkg/standing/standing.go` does not
reuse that pattern (or otherwise fail closed when the default branch is
unknown), so the gap is a real regression versus an established convention in
the same tree, not a hypothetical edge case.

Correction: in `standingEnvelope`/`safePublicationBranch`, either default an
empty `defaultBranch` the same way `pkg/worktree/reap.go` does, or refuse
publication outright (fail closed) whenever `defaultBranch` is empty, rather
than falling back to comparing against the literal string `"main"` alone.

## Residual risk if merged as-is

Any Herdforge deployment that configures `branch_publication: lane-push`
without also setting `project.default_branch`, on a repository whose trunk is
not literally `main`, silently grants autonomous git-write lanes push
authority to that trunk. Given this commit's own stated purpose is closing
exactly that class of gap, this should return to the author rather than ship
with a documented workaround.
