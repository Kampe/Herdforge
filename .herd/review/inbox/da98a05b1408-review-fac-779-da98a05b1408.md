- Diff is scoped exactly as claimed: `mutateStatusFullSchemaPUT` in
  `pkg/provider/kaneo_fence.go` now returns an error (no PUT) on a failed
  `GetTask`, a nil task, or a project-ID mismatch, instead of silently
  falling back to `{"status": status}`. This is the fail-closed fix the
  Context section describes (source: `mutateStatusFullSchemaPUT swallows
  GetTask errors and sends {status} alone`), and it is disproven-then-proven
  by the RED/GREEN swap above rather than merely asserted.
  On success it still builds the identical full-schema payload
  (title/description/priority/projectId/position-if-known) that existed
  before this patch — no field or position-semantics regression.
- `CoreTaskReads` is now threaded from `CoordinatorBrokerOptions` →
  `StartCoordinatorBroker` → `FenceBrokerConfig` → the broker's own
  `up := NewKaneoProvider(...)` upstream client (`pkg/provider/fence_broker.go:175`),
  and from `OpenClaimStack` into its `FenceBrokerConfig` literal
  (`pkg/provider/claim_stack.go:290`, guarded `k != nil && k.CoreTaskReads`
  so a nil provider can't panic). This closes exactly the gap the Context
  section names ("CoreTaskReads fixes the outer read but is not carried
  into the broker's upstream client") and is covered by a real assertion
  (`TestCoordinatorBrokerPropagatesCoreTaskReadConfiguration` checks
  `cb.Broker.upstream.CoreTaskReads`), not just a config-shape test.
  `factory_config.go` already forwarded `CoreTaskReads` before this patch
  (unchanged) — the fix is specifically the broker/coordinator-owned path.
- Auth headers, request timeout/deadline wiring (`WithOpDeadline`,
  `RetryRead`), and `authorizeKaneo` call sites are untouched by this diff —
  no behavior change to authentication or fencing beyond the prerequisite
  gate itself.
- Reject-all is excluded as a false PASS: the new
  `TestMutateStatusFullSchemaPUT_RejectsErrorAndWrongProjectPrerequisites`
  server returns `400` on any PUT it receives, and the assertion is
  `putCount == 0` (not "request failed") — so a client that "fails" by
  attempting-and-erroring on a bad PUT could not spuriously pass; only zero
  attempted PUTs satisfies it.
- Only in-scope files touched:
  `pkg/provider/{claim_stack,fence_broker,fence_mint_authority,kaneo_fence}.go`
  and their two test files. No lease/TTL, mint-authority redesign, live
