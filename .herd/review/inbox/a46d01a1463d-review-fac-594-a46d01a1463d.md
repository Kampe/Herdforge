What FAC-594 changes: when the reconciliation observer's fallback task-binding path finds an idle/terminal generationless tab with an authenticated completion-callback handoff, it previously closed the tab (TabSafeFinished) on handoff alone. This candidate adds a provider-settlement layer: (1) TabBinding/CompletedTaskProof now carry TaskID end-to-end so the completion proof can be tied to an exact provider task, not just a mail callback; (2) herdrControlCompletionProof.CompletedTaskProof fetches the exact provider task by ID, requires its status to normalize to something other than UNKNOWN (fail-closed otherwise, EvidenceError), and sets DeliverySettled only when status==Done; (3) ObserveReconciliation now branches three ways for a fallback-bound tab with a present, matching proof: agent.Status != "done" on a standing lane keeps it TabStanding (an idle/paused standing owner is not proof of finished work); proof.Value.DeliverySettled==false keeps it TabPreservedReview (handoff happened but the provider task isn't done, e.g. still in review); only exact done+settled reaches TabSafeFinished, which now also carries RearmLane when the tab belongs to a configured standing lane. (4) ReapCompletedTaskLanes refuses to close a decision carrying RearmLane if no RearmStanding adapter is wired (fail-closed, tested), and on successful close, calls RearmStanding(ctx, lane) via a wrapper around the existing runStandingConfigMode(..., ModeRaise, ...) path, recording Rearmed/Errs separately from Reaped. (5) configuredStandingLaneForAgent resolves the acting agent name against the configured roster using only exact repository-scoped or legacy standing identities (AgentNameForRepository / AgentName) — a prefix or pane-label lookalike does not grant rearm authority, and an ambiguous double-match fails closed with an error rather than guessing.
