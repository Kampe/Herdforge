What it does: adds `herd deps migrate --ref <task>` (both dry-run and
--apply) so a single named task can be migrated to herd-deps-v1 provenance
fences without a full-board scan. `PlanMigrationForRef`/
`PlanMigrationForRefWithProgress` resolve the task via `resolveMigrationTask`,
require the store to implement `scopedSnapshotter`, and walk only that task's
relation component via the new `snapshotGraphForMigrationTask`, which fetches
every task purely by exact ID/ref (never via `hydrateFresh`/board list) and
cross-checks id/ref/project on each hop so an endpoint can't smuggle in an
out-of-project or mismatched-identity task. `resolveMigrationTask` also
rejects terminal (done/archived) and unreadable-status tasks, and refuses on
ambiguous ref matches.

`ApplyMigrationForRef` re-plans from a fresh scoped snapshot per apply,
re-resolves task identity via `resolveMigrationTask` again right before
mutation (not just the original `tp.GetTask`), and — unlike the pre-existing
board-wide apply path — treats journal-write failures as hard errors with
rollback, and adds a post-write provider-side confirmation (re-snapshot,
compare provider revision and edge multiset) in addition to the existing
description-readback check. This is strictly more paranoid than the
board-wide path for the single-task case, which is the right shape for a
command intended to be run against a live board for one specific card.

Two small, deliberate provider hardenings ride along: `kaneo.go`'s
`decodeKaneoTaskBody` and `memory.go`'s `MemoryProvider.GetTask` both used to
silently return the first ref match when multiple tasks shared a ref; now
both collect all matches and hard-error listing the colliding IDs when more
than one is found (single match still returns normally). This directly
supports the "exact identity, no implicit accept" guarantee the new
ref-scoped path depends on, and is itself covered by
`TestDecodeKaneoTaskBody_DuplicateExactRefFailsClosed`.

CLI wiring in cmd/herd/deps.go: `--ref` is parsed, `fs.Visit` distinguishes
"flag not passed" from "flag passed empty" (refuses the latter), and both
the dry-run and --apply branches switch to the *ForRef functions when a ref
is selected. The `HERD_DEPS_MIGRATE_APPLY=1` coordinator-only gate is
untouched and still applies uniformly regardless of --ref.
