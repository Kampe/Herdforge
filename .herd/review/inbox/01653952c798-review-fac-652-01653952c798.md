## Findings

1. [High] Non-pipe refusal leaves the supplied descriptor open.

   `pkg/provider/fence_mint_authority.go:132-137` returns after `unix.Fstat`
   identifies a non-pipe, before `os.NewFile` installs the close defer. Thus a
   present regular-file descriptor survives the refusal even though the packet
   requires the inherited descriptor to close on every refusal. A temporary
   compiling control test that opened a regular file, set `HERD_FENCE_MINT_FD`,
   invoked `NewFenceBrokerMinterFromInheritedFD`, and then called `unix.Fstat`
   was RED (exit 1: descriptor remained open). The tracked test suite masks this
   path: `pkg/provider/claim_stack_mint_fd_test.go:373-379` explicitly says
   non-pipe descriptors are left open, and the regular-file subtest passes
   `fd=0` to its cleanup assertion. Close the owned/supplied descriptor on the
   non-pipe return as well, while preserving marker removal and avoiding a
   double-close.

2. [High] The actual Herdr agent marker can still opt into the in-process mint
   authority.

   `pkg/provider/fence_mint_authority.go:336-343` makes
   `coordinatorOwnsBroker()` deny `worker`, `builder`, and `reviewer`, but not
   `agent`. `pkg/provider/claim_stack.go:291-334` uses that predicate to enter
   `StartCoordinatorBroker` and stores its fresh minter in `stack.Minter`.
   Therefore a task/reviewer process carrying the native `HERD_ROLE=agent`
   marker can set `HERD_FENCE_COORDINATOR=1` and receive in-process mint
   authority without an inherited-FD refusal. A temporary compiling control
   test of exactly those environment values was RED (exit 1: the process was
   allowed to own the broker). Extend the same task-agent denial set to this
   in-process route and add a production-entry-point regression test. The
   role marker is caller-scrubbable, so it must remain deny-only defense in
   depth; no role value may be the positive grant, but the actual native agent
   marker must not be omitted from the refusal set.
