Scope: cmd/herd/main.go, cmd/herd/review_pool.go, cmd/herd/review_routing_test.go, pkg/router/route.go. Risk tier: R2 (routing/launch decision logic for the review fleet; no auth/secrets/destructive paths touched).

Problem addressed: `herd route qa` (advertise, via Router.Pick) and pool review launch (`resolvePoolReviewer`, via Router.Decide) previously consumed two independent quota reads and two independent live-agent counts. Pick's live count scanned all agents fleet-wide with no workspace scoping, while Decide never counted live agents at all. That split let route advertise a tuple that launch then refused, and the counted-agent set at advertise time did not reflect what launch would actually check. The commit message and reproduction test both point at a concrete 2026-08-30 W4 incident matching this description.

Fix, verified by reading (no go toolchain available in this sandbox to build/test — see limitation note below):

1. `resolveReviewerRouteAuthority` (cmd/herd/review_pool.go:888) is now the single authority function used by both `runRouteCommand("qa", ...)` (cmd/herd/main.go:7474) and `resolvePoolReviewer` (cmd/herd/review_pool.go:949). Both call sites fetch quota via the same `usage.FetchSnapshotCached()` path and route through the same `SurfaceRouter.Decide(...)` call with `StrictQuota: true`, eliminating the previous Pick/Decide divergence for the qa shape specifically. Non-qa shapes are untouched and still use the lenient `Pick` path with unconditional live-count probing — confirmed this is intentional and scoped correctly (`shape == reviewerRouteTaskShape` gate at main.go).
2. `liveRouteCount` (main.go:7424) now filters the herdr agent roster to `os.Getenv("HERD_WORKSPACE")` when set, via `strings.EqualFold` against `agent.Workspace` (confirmed `AgentEntry.Workspace` maps to json `workspace_id`, matching the test fixture's `"workspace_id":"w5"` field). When no workspace is set, `resolveReviewerRouteAuthority` deliberately does not attach `LiveCount` at all (comment: "do not invent a cross-workspace concurrency authority") rather than falling back to the old global count — a reasonable fail-safe rather than a silent behavior regression, and it's exercised by `TestLiveRouteCountScopesExplicitWorkspace`.
3. `--model` override for `qa` now goes through the same authority function instead of a separate ad-hoc Decide call that previously lived inline in `resolvePoolReviewer`; the explicit-model and default-pick paths can no longer diverge in family/pool derivation.
4. `Route` struct (pkg/router/route.go:665) gained `DecisionAuthority`, `CacheAge`, `Workspace` fields (all `omitempty`) so a reviewer route's JSON output can be checked against what launch actually used — additive, no existing consumer breaks.
