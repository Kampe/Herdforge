## Change

`pkg/mergeadmit/reconcile.go`: `ProveEquivalentLanded` gains a fallback path
for GitHub-style rebases where an administrative empty "worktree anchor"
commit sits ahead of the reviewed content commits, and where main-side
context changes can alter an intermediate content commit's patch ID even
though the overall reviewed change is preserved on landing.

- New `nonEmptyCommits` filters the candidate range down to commits whose
  `git diff-tree -p` output is non-empty, dropping administrative anchors
  before patch-ID comparison. An entirely empty candidate range is now a hard
  refusal (previously would have proceeded to `patchIDs` with the anchor
  included).
- The existing `matchOrderedPatchSubsequence` path is tried first and, on
  success, returns via a new shared `equivalentLandedProof` helper
  (`ordered-patch-subsequence-on-landed`) — this preserves current passing
  behavior for the common single/unaltered-context case.
- On ordered-match failure with a multi-commit candidate, a new
  `matchCombinedRangeReplay` looks for a landed-commit window the same length
  as the candidate whose tip patch ID matches the candidate tip, then uses
  `git merge-tree --write-tree --merge-base <base> <window-start-parent>
  <candidate>` to replay the reviewed base..candidate diff onto that window's
  parent and compares the resulting tree to the landed window's actual tip
  tree. Exactly one matching window is accepted (`combined-range-replay-on-landed`);
  zero or ambiguous (>1) matches are refused with a descriptive error.
- Single-commit candidates are explicitly excluded from the fallback ("Keep
  the established single-content-commit predicate unchanged") and continue to
  fail closed on ordered-match failure, unchanged from prior behavior.

`pkg/mergeadmit/reconcile_test.go` adds:
- `TestProveEquivalentLandedContextChangedStack`: constructs the exact FAC-681
  shape (empty worktree anchor + two content commits, with main-side context
  drift on the shared file), asserts the ordered proof would NOT match
  (`wantFirst == gotFirst` check fails, i.e. the fixture actually reproduces
  the described bug) before asserting the combined-replay proof succeeds with
  `Method == "combined-range-replay-on-landed"` and the correct `MergeSHA`.
  Also drives it through `Gate.ReconcileLanded` end-to-end and confirms the
  sealed receipt round-trips (`Digest == ComputeDigest()`).
- `TestProveEquivalentLandedContextChangedStackMutationControls`: four
  negative-control mutations of the landed side (omitted reviewed commit,
  changed reviewed commit, reordered reviewed commits, substituted unreviewed
  commit) — each must still be REFUSED by `ProveEquivalentLanded`. The
  "reorder" case additionally asserts its own fixture validity (candidate tip
  patch must differ from landed tip patch) so the control isolates the
  ordered-endpoint binding rather than accidentally passing via the ordered
  path.
