## Findings and risk

Reviewed exact range `78bc5b0c0e29a8c6ff16df33bf0ee058e42fdf0e..14165adec1225fca87afb48e2a0f7c86f43a4e53`; `herd review-classify` gives an R3 floor with deterministic verification, different-family review, security-capable review, and high-risk explicit gates. The implementation preserves worktrees and branches in the supplied happy-path fixtures, but the authorization and close paths are not safe for R3 approval.

1. **[Blocker] Enrollment accepts unstructured/stale reports and binds retirement to current HEAD instead of the accepted candidate.** `pkg/herdr/source_retirement.go:522-539` treats any uppercase text containing `READY` as proof, including `NOT READY`, quoted instructions, stale reports, and contradictory content. Lines `549-555` then set `CandidateSHA` from the worktree's current `HEAD`, ignoring both the launch receipt's `CandidateSHA` and the report's candidate. An accepted handoff for candidate A followed by a later worktree HEAD B therefore enrolls and can retire B without a durable READY handoff for B. This directly violates exact-candidate structured handoff authorization.

2. **[Blocker] Missing or ambiguous launch provenance can still authorize retirement.** `pkg/herdr/native_source_retirement.go:114-133` returns an empty receipt when no exact receipt is found and matches by broad OR conditions (task, name, worktree, or branch). `pkg/herdr/source_retirement.go:203-217` validates launch fields only when any are present, so an empty receipt passes. Enrollment also invents `session-<name>` at lines `600-601` and does not bind the receipt's session generation. A valid-looking manifest can therefore close without an accepted exact launch/session/incarnation.

3. **[Blocker] The close path can kill a replacement session after the original identity disappears.** `pkg/herdr/native_source_retirement.go:409-420` falls back to `hardCloseTab(m.TabID, m.AgentName)` when the exact live row is absent. `hardCloseTab` matches tab ID or name and constructs a fresh identity from whichever row it finds. `pkg/herdr/live_harness_proof.go:232-240` additionally calls the same broad fallback after `CloseExactTab` already performed absence readback. If the old tab is gone and a replacement uses the same agent name (or a reused tab ID), the fallback can close the replacement despite changed pane/session identity, violating the packet's PID/pane/start-identity race gate.

4. **[High] Process readback fails open after close.** `pkg/herdr/native_source_retirement.go:432-439` returns success for every `paneProcessesForRetirement` error, although that helper only classifies `ErrPaneNotFound` as expected absence and returns transport/permission/unknown errors unchanged. The caller then journals `close-done`, writes a retirement receipt, and can mark complete without proving residual processes are gone.

5. **[High] Active descendants are detected by a narrow name substring allowlist, and `ProcessPresent` is ignored by policy.** `pkg/herdr/native_source_retirement.go:210-215` records only names containing `test`, `build`, `go`, `git`, or editor names; `pkg/herdr/source_retirement.go:287-289` rejects only that filtered list. Active `python`, `node`, `make`, shell, or other verification/editing descendants can leave an idle lane eligible for close. This does not satisfy the unexpected-descendant/active-verification gate.

6. **[High] The claimed coordinator lifecycle integration is unwired.** `cmd/herd/drainadapt.go:106-113` installs only `retireReviews` in `drainActionHooks`; `cmd/herd/main.go:8750-8756` has no source-retirement hook, and `main.go:8953-8959` invokes only review retirement. Graph callers for `retireSourceLanes` are zero. The new function is therefore dead from the coordinator drain path; only the separate cleanup command reaches `runSourceRetirementCleanup`, so post-handoff/lifecycle sweep retirement is not actually integrated.

7. **[Medium] Default dry-run mutates durable state.** `cmd/herd/main.go:4565` defaults cleanup to dry-run, but `cmd/herd/source_cleanup_native.go:28-30` always calls enrollment, whose `pkg/herdr/source_retirement.go:632-634` appends manifests. `herd cleanup --dry-run` can therefore create/update the retirement registry even though it must be report-only.

8. **[Medium] Enrollment suppresses registry read errors.** `pkg/herdr/source_retirement.go:492-500` ignores the error from `registry.Latest()` and may append new manifests after a corrupt/unreadable journal. This is a fail-closed violation and can create durable state while prior lifecycle state is unknown.
