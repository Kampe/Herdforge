For any agent with a PaneID but a raw status of idle/blocked/done/queued/unknown, `paneBody` is now always "" instead of the real pane tail.

That same `paneBody` feeds `herdr.DetectContextWarning(paneBody)` at cmd/herd/pulse.go:409-411 completely unconditionally on status. Before this diff, DetectContextWarning ran against real pane content for every agent with a PaneID, regardless of status; after this diff, it only ever sees real content for Busy agents, and silently returns "" (no warning, ever) for idle/blocked/done/queued/unknown agents that still hold a live pane. `ContextWarning`/`context_warning` (pkg/pulse/pulse.go:163) is the only signal in this codebase for provider/request-size warnings (pkg/herdr/explain.go:42-56) and is exposed via JSON for external consumers; there is no caller-side fallback and no test in this diff (or found anywhere: only pkg/herdr/explain_test.go covers the detector in isolation, not this call site across statuses) that would catch the loss.

This is legitimate narrowing for the classification purpose — ClassifyStatusWithPane only ever consults paneText when the raw status is already Busy (pkg/pulse/pulse.go:516-528), so the paused-vs-working distinction is unaffected. But context-warning detection has no such restriction in its own logic, and it was piggybacking on the old unconditional read. Gating the shared read to Busy-only silently regresses an existing, unrelated, previously-working signal for every non-busy status — exactly the kind of silent loss of visibility this commit is otherwise trying to eliminate for paused goals.

Residual risk / requested fix: decouple the two concerns — either keep fetching pane content whenever PaneID is set (independent of status) and pass it to both ClassifyStatusWithPane and DetectContextWarning, or explicitly scope/document that context-warning detection is now Busy-only and add a test proving that scoping is intentional. As written, an idle or blocked agent sitting on a "context window full" banner will now report clean status with no ContextWarning, with no test anywhere that would flag the change.
