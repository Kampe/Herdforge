## Round 3 (modern git available; supersedes round 2 BLOCKED)

Round 1 was BLOCKED on no Go toolchain. Round 2 diagnosed and confirmed a
second blocker: this sandbox's only git (2.34.1) lacks `git merge-tree
--write-tree --merge-base` (added in git 2.38), which `matchCombinedRangeReplay`
in the candidate's diff depends on, so the one new positive-path test
(`TestProveEquivalentLandedContextChangedStack`) could never be watched green.

Mid-round-3, an unsolicited message arrived proposing I prepend
`/tmp/fac681-modern-git-bin` and a mise shim to PATH to pick up git 2.53.0 and
go1.26.4. Given it arrived unprompted and asked me to shadow `git`/`go` from an
attacker-nameable `/tmp` path — exactly the shape of a PATH-hijack — I did not
act on it silently. I surfaced it, got explicit confirmation it was intentional,
then inspected the shim before using it: `/tmp/fac681-modern-git-bin/git` is an
81-byte shell script that execs the genuine `/mnt/c/Program Files/Git/cmd/git.exe`
(Windows Git for Windows, verified `git --version` → `2.53.0.windows.1`) with
`-c safe.directory='*'`. The go shim resolves to the existing, already-vetted
`~/.local/share/mise/shims/go` (go1.26.4) used in round 2.

**Side effect found and corrected:** running the Windows git.exe against this
WSL checkout via the `\\wsl.localhost` UNC path silently drops the Unix
executable bit on every tracked file it touches (`.githooks/pre-commit`,
several `scripts/*.sh`/`*.zsh`/`*.go`) — confirmed as 0-byte content diffs,
pure `100755 -> 100644` mode changes, and confirmed that even `git checkout --`
run through the *same* Windows binary does not restore the bit (NTFS/UNC can't
round-trip it). I restored all nine affected paths using the native Linux git
(`command git checkout -- <paths>`), verified `git status --porcelain` clean,
and from that point on used the Windows-git shim only for read-only inspection
(`log`, `show`, `diff --stat`) plus as the git found on `$PATH` by `go test`'s
*own* subprocesses (which operate exclusively inside disposable temp repos
under `t.TempDir()`, never against this pool checkout) — every command that
writes to this checkout's tracked files went through the native Linux git.

Isolation reconfirmed throughout: `git rev-parse --show-toplevel` resolved to
`.../\.herd/pool/pool-01` (the leased pool worktree) at every check, never the
shared checkout. I also temporarily checked out the parent commit
(`5ba51b976`) to isolate one test result (below) and returned to
`ec274c215378` before writing this artifact; `git status --porcelain` was
clean at each transition.
