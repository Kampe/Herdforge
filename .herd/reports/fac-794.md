## Safety Fix 1: Durable Handoff Parser Hardening
- **Vulnerability / Flaw**: `ParseStructuredHandoffReport` previously permitted incomplete reports (missing task, agent, or candidate SHA), accepted non-ready verdicts, failed to reject contradictory duplicates (e.g. `Status: READY` followed by `Status: BLOCKED`), and misidentified markdown quoted prose (`> Task: ...`) or code fences (```) as top-level identity headers.
- **Production Guard (`pkg/herdr/source_retirement.go`)**:
  - Requires all four fields: `TaskRef`, `AgentName`, `CandidateSHA` (exact 40-character hex string), and `Status`.
  - Rejects non-ready verdicts (`BLOCKED`, `FAIL`, `WORKING`, `NOT READY`).
  - Detects duplicate keys and fails closed on conflicting status/task/agent/candidate definitions.
  - Strips markdown code fences (```...```) and block quotes (`> ...`) prior to header extraction.
- **RED Evidence (Without Parser Guards)**:
  - Input: Report with `Status: READY` and duplicate line `Status: BLOCKED` -> parser previously returned `Status: READY` (SILENT ACCEPTANCE of contradictory status).
  - Input: Report with `> Task: FAC-999` in quote block -> parser parsed `TaskRef: FAC-999` (PROSE INJECTION).
  - Input: Report missing `AgentName` -> parser returned partial report without error (IDENTITY BYPASS).
- **Restored GREEN Evidence (`pkg/herdr/source_retirement_test.go`)**:
  - `TestParseStructuredHandoffReport_ValidAndInvalid` runs 13 subtests:
    - `non_ready_status`: assertion `err != nil && strings.Contains(err.Error(), "not ready")` -> PASS
    - `conflicting_duplicate_status`: assertion `err != nil && strings.Contains(err.Error(), "conflicting duplicate status")` -> PASS
    - `conflicting_duplicate_task`: assertion `err != nil && strings.Contains(err.Error(), "conflicting duplicate task")` -> PASS
    - `quoted_prose_lines_ignored`: extracts actual header `FAC-794` ignoring `> Task: FAC-OTHER` -> PASS
    - `code_block_lines_ignored`: extracts actual header `FAC-794` ignoring code block contents -> PASS
    - `missing_agent`, `missing_task`, `missing_candidate`: assertion `err != nil` -> PASS

## Safety Fix 2: Launch Exact Authority & Start-Pin / Final-Candidate Authentication
- **Vulnerability / Flaw**: Builder launch receipts are generated at START time before code exists (where `CandidateSHA` is empty or the pre-launch base pin `BaseSHA`). Requiring `Launch.CandidateSHA == Manifest.CandidateSHA` rendered legitimate builder lane retirement universally inert, while accepting unauthenticated handoffs bypassed launch provenance.
- **Production Guard (`pkg/herdr/native_source_retirement.go` & `pkg/herdr/source_retirement.go`)**:
  - `findLaunchReceipt` and `EvaluateSourceRetirement` strictly bind repository identity, authorized source role (`worker`, `forge-smith`, `recovery`, `mender`), task, agent, branch, worktree, session ID, tab ID, and pane ID.
  - Authenticates launch receipt start pin (`r.CandidateSHA` either empty, equal to `m.BaseSHA`, or ancestor of `m.CandidateSHA`) against final candidate SHA created in worktree.
  - Rejects non-source roles (e.g. `reviewer`), foreign repositories, and ambiguous conflicting receipts.
- **RED Evidence (Pre-Fix Regressions)**:
  - When `Launch.CandidateSHA` was pinned to base commit `baseSHA` and worker committed `finalCandidateSHA`: `EvaluateSourceRetirement` returned `BLOCKED: launch provenance candidate SHA mismatch` (INERT CLEANUP BUG).
  - When non-source role receipt (`Role: "reviewer"`) was presented: `findLaunchReceipt` matched it and attempted to retire non-source lane (AUTHORITY LEAK).
- **Restored GREEN Evidence (`pkg/herdr/native_source_retirement_test.go`)**:
  - `TestNativeSourceRetirement_ProductionLaunchReceiptWithStartPinAndNewerFinalCandidate`:
    - Production launch receipt recorded with `CandidateSHA: baseSHA`.
    - Builder commits `finalCandidateSHA` in worktree and produces `REPORT` with `Candidate: finalCandidateSHA, Status: READY`.
    - `EnrollReadySourceManifests` enrolls manifest with `CandidateSHA = finalCandidateSHA, BaseSHA = baseSHA`.
    - `EvaluateSourceRetirement` returns `Eligible: true`.
    - `RetireSourceLanesContext` successfully closes tab, preserves worktree and branch intact (`Retired: 1, Blocked: 0, Failed: 0, err: nil`).
  - `TestNativeSourceRetirementBlocksNonSourceRoleAndAmbiguousReceipts`:
    - Receipt with `Role: "reviewer"` returns empty receipt (rejected).
    - Multiple conflicting receipts for same task/name return empty receipt (rejected).

## Safety Fix 3: Close-Time Process Tree Race Check
- **Vulnerability / Flaw**: A source lane might become active or spawn child processes between the initial observation phase and the final tab closure.
- **Production Guard (`pkg/herdr/live_harness_proof.go`)**:
  - `CloseSettledSourceTab` calls `pane process-info` immediately prior to issuing the closed call; aborts if any foreground or descendant process (e.g. `make`, `go test`, active command) is active.
- **RED Evidence**:
  - Tab observed as idle, but `make test` starts right before close -> previously closed tab during test run.
- **Restored GREEN Evidence (`pkg/herdr/native_source_retirement_test.go`)**:
  - `TestCloseSettledSourceTabRejectsActiveProcessesAtCloseTime`:
    - Injected live pane with active process `make test`.
    - `CloseSettledSourceTab` returns error containing `active non-idle processes` and refuses tab close.

## Safety Fix 4: Mixed-Batch Fail-Closed Isolation & Non-Zero Error Aggregation
- **Vulnerability / Flaw**: In a mixed batch of source manifests, a failure in one lane could abort processing for all lanes, or observation/mutation errors could be swallowed without propagating non-zero errors.
- **Production Guard (`pkg/herdr/source_retirement.go` & `cmd/herd/drainadapt.go`)**:
  - `RetireSourceLanesContext` executes per-lane evaluation and mutation: eligible own settled lanes progress and retire cleanly (`r.Retired++`), while invalid/failing lanes fail closed (`r.Failed++`) and blocked lanes remain intact (`r.Blocked++`).
  - Aggregates all observation and mutation errors into a non-nil error return whenever `r.Failed > 0`.
- **RED Evidence**:
  - Batch with 1 eligible lane and 1 observation failure -> previously either halted before retiring eligible lane OR returned `err == nil` swallowing observation failure.
- **Restored GREEN Evidence (`pkg/herdr/source_retirement_test.go`)**:
  - `TestRetireSourceLanesContext_MixedBatchFailClosedIsolation`:
    - Batch contains: `mEligible`, `mFailObs` (observation error), and `mBlocked` (dirty worktree).
    - Result: `report.Retired == 1`, `report.Blocked == 1`, `report.Failed == 1`.
    - `mEligible` completes all lifecycle phases (`revalidate` -> `journal-close-intent` -> `close` -> `verify-absence` -> `journal-close-done` -> `receipt` -> `journal-complete`).
    - `RetireSourceLanesContext` returns non-nil aggregated error describing the failure.

## Safety Fix 5: `.herd/herd.yaml` Absence vs Malformed Configuration
- **Vulnerability / Flaw**: Missing `.herd/herd.yaml` in minimal/WSL environments threw unexpected errors, but ignoring errors completely risked hiding malformed syntax or permission errors.
- **Production Guard (`cmd/herd/source_cleanup_native.go`)**:
  - Distinguishes `errors.Is(err, os.ErrNotExist)` (configuration absence is harmless when no cleanup authority configured) from real syntax/validation errors (`!errors.Is(err, os.ErrNotExist)` fails closed).
- **RED Evidence**:
  - Malformed YAML in `.herd/herd.yaml` -> previously silently fell back to nil config instead of failing.
- **Restored GREEN Evidence (`cmd/herd/source_retirement_cli_test.go`)**:
  - `TestSourceCleanupNative_HerdYamlAbsenceVsMalformed`:
    - Missing `.herd/herd.yaml`: returns `report.Retired == 0, err == nil`.
    - Malformed `.herd/herd.yaml`: returns `err != nil` (fails closed).
